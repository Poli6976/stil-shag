# Как включить депозит и оплату

Код готов (`db/schema.sql`, `lib/wallet.js`, `lib/payments/robokassa.js`,
`api/payments/*`, `api/orders/create.js`, `api/wallet/*`, `api/config.js`,
вход и баланс в `cabinet.html`/`js/wallet.js`), но чтобы это реально
заработало, нужно завести два внешних сервиса и прописать их ключи в Vercel
— так же, как уже сделано для GigaChat (`DEPLOY-photo-analysis.md`) и кодов
«Примерки» (`DEPLOY-partner-codes.md`).

**История платёжного провайдера:** сначала пробовали ЮKassa (2026-08-13,
заявка так и не была доведена до конца), потом Prodamus (код был написан,
магазин зарегистрирован, но 2026-08-17 Prodamus прислал окончательный отказ
в сотрудничестве без объяснения причин и заблокировал кабинет) — теперь
Robokassa, ниже актуальная инструкция именно под неё.

---

## Важно прочитать перед началом: про «зарубежные карты»

Изначально обсуждалась оплата зарубежными картами с конвертацией валюты.
Это технически не работает для российского ИП/самозанятого/ООО прямо
сейчас: Visa и Mastercard отключили карты российских банков от
международного процессинга ещё в марте 2022 года, и ни один российский
эквайринг не может провести карту, выпущенную зарубежным банком, на счёт
российского юрлица. Поэтому ниже подключается приём **рублёвых** платежей
(карты российских банков + СБП) — это единственное, что реально работает
в вашей юрисдикции. Если в будущем появится юрлицо или счёт за рубежом —
для мультивалютной оплаты понадобится второй платёжный провайдер (например
Stripe), это отдельная задача с другими вводными.

## Как это устроено (без технического жаргона)

Раньше в личном кабинете не было ни аккаунтов, ни денег — только демо на
localStorage. Теперь:

1. Клиент входит по email (без пароля — присылаем одноразовую ссылку).
2. Пополняет депозит на любую сумму — переходит на страницу оплаты Robokassa,
   вводит карту там (её номер и CVC никогда не попадают на ваш сайт).
3. После оплаты Robokassa присылает сайту подписанное уведомление (ResultURL),
   и баланс клиента в базе увеличивается автоматически.
4. Консультация виртуального стилиста и «Примерка» списываются с этого
   баланса — если денег не хватает, сайт вежливо попросит пополнить депозит.
5. Сами деньги оседают на счету Robokassa и переводятся на **ваш расчётный
   счёт**/счёт самозанятого по графику выплат, который вы укажете при
   регистрации магазина в Robokassa (см. шаг 2 ниже) — это происходит на
   стороне Robokassa, в код сайта реквизиты счёта не попадают вообще.

## 1. Завести проект в Supabase (аккаунты и база данных)

1. Зарегистрироваться на [supabase.com](https://supabase.com), создать
   новый проект (бесплатного тарифа достаточно для старта).
2. **Project Settings → API** — скопировать оттуда три значения:
   `Project URL` → это `SUPABASE_URL`, `anon public` ключ → это
   `SUPABASE_ANON_KEY`, `service_role` ключ → это `SUPABASE_SERVICE_ROLE_KEY`
   (он даёт полный доступ к базе в обход всех проверок — обращаться с ним
   как с паролем от всего, никогда не публиковать).
3. **SQL Editor** в Supabase — открыть, вставить целиком содержимое файла
   [`db/schema.sql`](db/schema.sql) из этого проекта, выполнить. Создаст
   таблицы для баланса, платежей и заказов, а также правила доступа (RLS),
   которые не дают одному клиенту прочитать чужой баланс.
4. **Authentication → Providers** — по умолчанию Email-вход (magic link)
   уже включён, ничего дополнительно настраивать не нужно для старта. При
   желании можно настроить свой домен для писем со ссылкой входа
   (Authentication → Email Templates / SMTP Settings) — необязательно.

## 2. Завести магазин в Robokassa (приём платежей)

1. Зарегистрироваться на [robokassa.ru](https://robokassa.ru) — «Создать
   кабинет», форма ведения бизнеса **«Самозанятый»**, ИНН. Заявка на
   активацию рассматривается 1–3 рабочих дня — расчётный счёт/реквизиты
   самозанятого указываются на стороне Robokassa (не в этот проект и не в
   переменные окружения).
2. **Требования Robokassa к сайту перед подключением** (проверено 2026-08-17,
   все пять пунктов на сайте закрыты): ресурс публично доступен, актуальное
   описание услуг, есть оферта (`legal-offer.html`), контактный email открыто
   на сайте (подвал каждой страницы + `index.html`), реквизиты продавца
   (ИНН/имя самозанятого) в подвале каждой страницы. **Телефона для связи на
   сайте нет** — Robokassa в требованиях просит и email, и телефон; сейчас
   указан только email, если проверка потребует телефон — обсудить с
   пользователем, какой номер публиковать.
3. В личном кабинете Robokassa — **Настройки магазина**: скопировать
   `MerchantLogin` → это `ROBOKASSA_MERCHANT_LOGIN`, «Пароль #1» →
   `ROBOKASSA_PASSWORD1`, «Пароль #2» → `ROBOKASSA_PASSWORD2`.
4. Там же указать статически (не параметрами запроса, код их не передаёт):
   **ResultURL** = `https://ВАШ-ДОМЕН/api/payments/webhook` (сервер-сервер
   уведомление о зачислении), **SuccessURL**/**FailURL** — оба на
   `https://ВАШ-ДОМЕН/cabinet.html` (браузер вернётся туда после оплаты).
5. Пока магазин на проверке — у Robokassa есть тестовый режим (`IsTest=1`,
   включается переменной `ROBOKASSA_DEMO_MODE=1` ниже), им и стоит проверить
   весь цикл перед реальным запуском (см. раздел «Проверить» ниже).

## 3. Прописать переменные окружения на Vercel

**Project → Settings → Environment Variables**, добавить:

| Имя | Значение |
|---|---|
| `SUPABASE_URL` | из шага 1.2 |
| `SUPABASE_ANON_KEY` | из шага 1.2 |
| `SUPABASE_SERVICE_ROLE_KEY` | из шага 1.2 |
| `ROBOKASSA_MERCHANT_LOGIN` | из шага 2.3 |
| `ROBOKASSA_PASSWORD1` | из шага 2.3 |
| `ROBOKASSA_PASSWORD2` | из шага 2.3 |
| `ROBOKASSA_DEMO_MODE` | `1` на время проверки, потом удалить |

Сохранить → **Redeploy** (просто сохранить недостаточно, нужен именно
передеплой — та же грабля, что с GigaChat-ключом).

## 4. Проверить

1. Открыть `.../cabinet.html`, ввести email в разделе «Вход», получить
   письмо со ссылкой, перейти по ней — должен появиться раздел «Баланс» с
   суммой 0 ₽.
2. Ввести сумму в поле «Пополнить», нажать — должно перекинуть на страницу
   оплаты Robokassa. С `ROBOKASSA_DEMO_MODE=1` это тестовый платёж, деньги не
   спишутся по-настоящему.
3. Вернуться на `cabinet.html`, обновить страницу — баланс должен
   увеличиться на оплаченную сумму (может занять несколько секунд, пока
   дойдёт вебхук).
4. В истории операций должна появиться строка о пополнении.
5. **Обязательно** — открыть в личном кабинете Robokassa лог отправленных
   уведомлений и свериться с реальным телом запроса: код в
   `api/payments/webhook.js` ожидает поля `OutSum`, `InvId`,
   `SignatureValue` и отвечает текстом `OK<InvId>` — если Robokassa
   называет поля иначе или ждёт другой формат ответа, поправить
   `api/payments/webhook.js`/`lib/payments/robokassa.js` по факту (эти
   названия взяты из документации, а не проверены вживую).
6. Прежде чем принимать реальные деньги — убрать `ROBOKASSA_DEMO_MODE` из
   переменных окружения и передеплоить.

нужно **выполнить его ещё раз** (SQL Editor → вставить содержимое файла

(`if not exists`/`create or replace`), новые строки просто добавят колонку
`wallets.free_look_used` и функцию `consume_free_look`, остальное не
изменится.

## Обновление 2026-08-26 — временный ручной канал СБП, пока Robokassa на проверке

Прямой карточный эквайринг без агрегатора (Т-Банк, CloudPayments) недоступен
самозанятому без ИП — у него нет расчётного счёта, поэтому агрегатор всё
равно нужен. Пока заявка в Robokassa рассматривается, в личном кабинете рядом
с «Пополнить картой» есть кнопка «Оплатить по СБП» — клиент переводит деньги
**вам лично** по номеру телефона, а зачисление на депозит вы подтверждаете
вручную. Это ручной труд на каждый платёж и отдельная фискализация через
«Мой налог» для каждого перевода — не забывайте это делать, автоматической
интеграции с ФНС здесь нет (в отличие от Robokassa).

1. Прописать в Vercel три переменные: `SBP_PHONE` (номер телефона, привязанный
   к вашей карте/счёту для перевода), `SBP_BANK` (какой банк), `SBP_RECIPIENT_NAME`
   (имя получателя, как в банке — некоторые приложения его показывают
   отправителю для сверки). Без всех трёх кнопка «Оплатить по СБП» будет
   отвечать ошибкой, ничего не сломается на остальном сайте.
2. Redeploy.
3. Когда клиент нажимает «Оплатить по СБП» в `cabinet.html`, сайт создаёт
   заявку (таблица `payments`, `provider = 'sbp'`, статус `pending`) и
   показывает ему ваш номер телефона, банк и короткий 6-значный код заказа —
   попросите указывать этот код в комментарии к переводу, иначе заявку будет
   сложнее сопоставить с реальным поступлением.
4. Откройте `.../admin-sbp-orders.html` (служебная страница, не для
   покупателей — не ссылается ниоткуда на сайте), введите `ADMIN_KEY`,
   нажмите «Показать заявки». Сверьте сумму и код заказа с реальным
   поступлением в своём банковском приложении, нажмите «Подтвердить оплату» —
   депозит клиента зачислится сразу той же функцией, что и у Robokassa.
5. Когда Robokassa одобрит заявку — кнопку «Оплатить по СБП» можно оставить
   (переходный период не помешает постоянному каналу) или убрать из
   `cabinet.html` отдельным изменением, когда решите, что она больше не нужна.
